# День 2 — редактор тестов

- `/tests/new`: новый документ без предварительного создания пустой записи в БД.
- `/tests/:testId/edit`: загрузка и сохранение существующего теста через `/editor`.
- Название, описание, вопросы, пояснения; пять типов ответа: один вариант, несколько, текст, пропуски, сопоставление.
- Добавление/удаление вопросов, вариантов и полей; изменение порядка. Удаление вопроса можно отменить до следующего редактирования.
- ID существующих вопросов сохраняются. Новые вопросы отправляются без ID. Вспомогательные ключи интерфейса в API не отправляются.
- Клиентская валидация перед сохранением; окончательная проверка и транзакция остаются на backend. После успешного сохранения редактор использует документ, возвращённый сервером.
- При ошибке сохранения введённые данные остаются на странице. Есть предупреждение при закрытии/перезагрузке и при переходе по ссылке «Мои тесты». Черновики автоматически не сохраняются; навигация кнопкой «Назад» браузера внутри SPA не блокируется.
- Во время сохранения поля заблокированы, чтобы ответ сервера не затёр новые правки.

## Проверка 4 октября 2026

Сборка, ESLint и 22 frontend-теста проходят (8 проверок модели редактора и 14 авторизации).

С реальным Docker backend/PostgreSQL в Chrome проверены: создание через главную, ошибки пустого документа, два вопроса, выбор правильного ответа, изменение порядка, сохранение нового документа, отмена удаления, изменение названия, добавление и перестановка вариантов, повторное сохранение, перезагрузка с теми же данными.

Тестовый аккаунт и созданный тест удалены после проверки. Backend и его схема для этого этапа не менялись.
