# Авторизация frontend

День 1 завершён 4 октября 2026 года.

## Поведение

- `/login` — отдельная форма входа; `/register` после успешной регистрации направляет на неё с заполненным email. Пароль между страницами не передаётся.
- Главная `/` и `/tests/:testId/edit` защищены. После входа восстанавливается исходный внутренний адрес. Внешние адреса для перенаправления запрещены.
- `/privacy` доступна без входа и без ожидания сервера авторизации.
- Вход обрабатывается общим модулем Session, подписка React — через useSyncExternalStore.
- Access-токен хранится только в памяти. Refresh — в sessionStorage текущей вкладки (ключ `quiz.refresh`), пароль не сохраняется.
- При перезагрузке страницы выполняются ротация refresh и загрузка `/users/me`. Обычное закрытие вкладки завершает локальную сессию. Восстановление вкладок средствами браузера может восстановить sessionStorage.
- При 401 от защищённого API выполняется один refresh и один повтор исходного запроса. Параллельные запросы разделяют один refresh. Повторный 401 или отклонённый refresh переводит на вход. 403 не запускает refresh.
- Ошибка сети при восстановлении позволяет повторить запрос; сохранённый refresh не удаляется просто из-за недоступности сервера.
- Выход вызывает `/auth/logout` с последним refresh и очищает локальную сессию. При сетевой ошибке пользователь видит ошибку и может повторить выход. Уже выпущенный access на backend действует до истечения срока — это существующий контракт API.

Хранилище sessionStorage доступно JavaScript этого origin. Это не HttpOnly cookie. Если позже понадобится постоянный вход между вкладками/перезапусками браузера, следует отдельно внедрить cookie-сессию с соответствующей серверной защитой. Дублирование вкладки может скопировать sessionStorage: после ротации одна из таких вкладок может потребовать повторный вход.

## Использование API

Новые защищённые страницы должны вызывать `apiFetch` из `src/api/client.ts`, а не прямой fetch с собственным токеном. Пути относительно `/api/v1`, например `apiFetch('/tests/')`. Тело JSON требует `Content-Type: application/json`; для FormData заголовок браузер задаёт сам.

`VITE_API_URL` — адрес backend без `/api/v1`, по умолчанию `http://localhost:8000`. Адрес frontend должен быть разрешён в CORS backend.

## Проверки

```bash
npm run build
npm run lint
npm test
```

14 тестов проверяют восстановление, ротацию, параллельные 401, отклонённые токены, ошибки сети, отсутствие бесконечных повторов, выход во время refresh, запоздалые запросы после выхода и безопасные адреса возврата.

В Chrome с Docker backend/PostgreSQL проверены: переход с защищённого редактора на вход, регистрация временного пользователя, вход с возвратом к редактору, перезагрузка с восстановлением сессии, переход на главную и выход. Отзыв обеих refresh-сессий подтверждён запросом к PostgreSQL. Временный пользователь удалён.

Регистрация по приглашению и сам редактор остаются задачами следующих дней.
