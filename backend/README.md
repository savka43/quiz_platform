# Backend API

Python 3.14, FastAPI, Pydantic v2, SQLAlchemy Async, PostgreSQL, Alembic, bcrypt и PyJWT. Публичного каталога нет: все данные принадлежат конкретному пользователю.

## Основные маршруты

Все пути ниже начинаются с `/api/v1`. Авторизация — access JWT, кроме `/auth/register`, `/auth/login`; для `/auth/refresh` и `/auth/logout` нужен refresh JWT.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/auth/register` | JSON email/password |
| POST | `/auth/login` | Form username=email/password, пара токенов |
| POST | `/auth/refresh` | Ротация пары токенов |
| POST | `/auth/logout` | Отзыв переданного refresh |
| GET | `/users/me` | Свой профиль |
| GET, POST | `/tests/` | Свои тесты / создание пустого теста |
| GET, PATCH, DELETE | `/tests/{id}` | Метаданные / изменение / удаление |
| POST | `/tests/document` | Создать тест с вопросами одной транзакцией |
| GET, PUT | `/tests/{id}/editor` | Документ редактора / сохранение всего документа |
| GET, POST | `/questions/` | Свои вопросы / добавить вопрос |
| GET, PATCH, DELETE | `/questions/{id}` | Получить / изменить / удалить вопрос |
| POST | `/import/pdf/preview`, `/import/html/preview`, `/import/json/preview` | Multipart file, только разбор |
| POST | `/import/pdf/confirm`, `/import/html/confirm`, `/import/json/confirm` | Сохранить исправленный документ |
| POST, DELETE | `/questions/{id}/favorite` | Добавить / убрать вопрос из избранного |
| GET | `/users/me/favorites` | Избранные вопросы |
| POST | `/favorites/attempts` | Попытка по выбранным избранным вопросам |
| POST | `/tests/{id}/attempts` | Начать прохождение своего теста |
| GET | `/attempts/{id}/questions` | Вопросы попытки без ключей |
| POST | `/attempts/{id}/answers` | Создать/заменить ответ |
| POST | `/attempts/{id}/finish` | Завершить и вычислить балл |
| GET | `/attempts/{id}/result`, `/attempts/{id}/mistakes` | Результат / ошибки после завершения |
| GET | `/users/me/attempts` | История |
| GET, POST | `/attempts/` | Свои попытки / старт с JSON test_id |
| GET, DELETE | `/attempts/{id}` | Своя попытка / удалить её с ответами |
| GET, POST | `/attempt-answers/` | Свои ответы / совместимый маршрут отправки |
| GET, PATCH, DELETE | `/attempt-answers/{id}` | Ответ / замена ответа / удаление до завершения |

`PATCH /attempts/{id}` оставлен для совместимости маршрутов, но возвращает `409`: используйте `/answers` и `/finish`.

Списки `/tests/`, `/questions/`, `/attempts/`, `/attempt-answers/` принимают `limit` (1–1000, по умолчанию 100) и `offset`. История и избранное — `limit` 1–100 (по умолчанию 20), `offset`.

## Документ редактора и подтверждения импорта

`POST /tests/document`, `PUT /tests/{id}/editor` и `POST /import/{format}/confirm` принимают одинаковую структуру:

```json
{
  "title": "HTTP",
  "description": "Основы",
  "questions": [
    {
      "text": "Какой код означает Not Found?",
      "question_type": "single_choice",
      "options": [
        {"text": "200", "is_correct": false},
        {"text": "404", "is_correct": true}
      ],
      "explanation": "404 означает, что ресурс не найден."
    },
    {
      "text": "Выберите чётные числа",
      "question_type": "multiple_choice",
      "options": [
        {"text": "2", "is_correct": true},
        {"text": "3", "is_correct": false},
        {"text": "4", "is_correct": true}
      ]
    },
    {"text": "Название протокола", "question_type": "text", "correct_answer": "HTTP"},
    {
      "text": "Заполните пропуски",
      "question_type": "fill_blank",
      "blanks": [{"prompt": "2 + 2", "correct_answer": "4"}]
    },
    {
      "text": "Сопоставьте",
      "question_type": "matching",
      "blanks": [{"prompt": "Not Found", "correct_answer": "404", "choices": ["200", "404"]}]
    }
  ]
}
```

Минимум один вопрос, максимум 1000. Для выбора — минимум два варианта, у `single_choice` ровно один правильный, у `multiple_choice` один или несколько. Текст и ответы не могут быть пустыми. Для сопоставления правильный ответ выбирается из `choices`.

Порядок вопросов и вариантов задаётся их порядком в массивах. В GET редактора у существующего вопроса есть `id`: оставляйте его при PUT для сохранения идентичности и избранного. Вопрос без `id` добавляется; отсутствующий в новом документе удаляется. На создании документа передавать существующие ID запрещено. Варианты ответа при сохранении заменяются; начатые попытки используют собственный снимок.

Прямой `POST /questions/` принимает поля вопроса и `test_id`. `PATCH /questions/{id}` принимает изменённые поля, затем проверяет целостность вопроса целиком. Родительский `test_id` менять нельзя.

## Импорт и превью

`file` — multipart файл `.pdf`, `.html`, `.htm` или `.json`, до 8 MiB. Поддерживается UTF-8 HTML/JSON; PDF должен иметь текстовый слой. MIME/расширение и содержимое проверяются, ошибки возвращаются как `413`, `415` или `422`.

JSON принимается в структуре редактора: объект `title`, необязательный `description` и массив `questions`. Поддерживаются типы `single_choice`, `multiple_choice`, `text`, `fill_blank`, `matching`. Неуказанная правильность вариантов попадает в превью как `null` и должна быть проверена до сохранения. Пример и запрос для ИИ находятся в [`docs/IMPORT_FORMAT.md`](../docs/IMPORT_FORMAT.md).

PDF-парсер разделяет номера вопросов и вариантов, учитывает переходы страниц, извлекает `Ответ:` и `Пояснение:`. Точное совпадение текста или однозначное сокращение помечается правильным. Номер в `Ответ: 2` трактуется как текст ответа `2`, а не автоматически как второй вариант.

HTML-парсер читает сохранённую страницу SyncShare: тексты, radio/checkbox, таблицы правильности, текстовые ответы, пропуски, сопоставление и MathML. Скрипты не выполняются, внешние ресурсы не загружаются. `checked` и количество голосов не считаются доказательством правильности. Отметка «Неизвестно» остаётся неизвестной.

Превью содержит:

```json
{
  "title": "Импорт",
  "source": "html_import",
  "question_count": 1,
  "needs_review_count": 1,
  "warnings": [],
  "questions": [{
    "number": 1,
    "text": "Вопрос",
    "question_type": "single_choice",
    "options": [{"text": "A", "is_correct": null}, {"text": "B", "is_correct": null}],
    "correct_answer": "",
    "blanks": [],
    "explanation": "",
    "source_answer": "",
    "warnings": ["Нужно проверить варианты"],
    "needs_review": true,
    "correct_option_count": 0
  }]
}
```

Frontend редактирует `text`, `question_type`, `options`, `correct_answer`, `blanks`, `explanation`, может добавлять/удалять вопросы и варианты. Для confirm он формирует **документ редактора** из этих полей, удаляя служебные `number`, `warnings`, `source_answer`, `needs_review`, счётчики и `source`. `null` в отметках правильности до сохранения нужно разрешить в `true`/`false`. Неизвестные ключи и неправильные сочетания полей отклоняются.

Preview не создаёт теста и не сохраняет загруженный файл. Confirm заново валидирует исправленные данные; создание Test/Question/AnswerOption выполняется одной транзакцией. При ошибке не остаётся половины теста.

## Прохождение

1. `POST /tests/{id}/attempts` → сохранить `id` попытки.
2. `GET /attempts/{id}/questions` → получить `attempt_question_id`, тексты и ID вариантов из снимка.
3. Для выбора:

```json
{"attempt_question_id": 10, "selected_option_ids": [42, 43]}
```

Для текста:

```json
{"attempt_question_id": 11, "user_answer": "HTTP"}
```

Для пропусков/сопоставления — ответы в порядке полей:

```json
{"attempt_question_id": 12, "blank_answers": ["4"]}
```

Можно использовать `question_id` вместо `attempt_question_id`, пока исходный вопрос существует. После его удаления используйте ID снимка. Одновременно оба идентификатора передавать нельзя.

4. Повторная отправка заменяет ответ до завершения. Правильность до завершения возвращается как `null`.
5. После ответа на все вопросы — `POST /attempts/{id}/finish`.
6. Читать `/result` и `/mistakes`. При ошибке показываются исходный вопрос, выбор пользователя, правильные варианты/поля и пояснение.

В множественном выборе нужен точный набор правильных вариантов, без лишних и пропущенных. Текст сравнивается без учёта регистра и лишних пробелов; математическая эквивалентность, синонимы и произвольное округление не вычисляются. Все вопросы имеют одинаковый вес, score — процент правильных, округлённый до двух знаков.

`is_correct`, `score`, `started_at`, `finished_at`, `user_id` не принимаются от клиента. Проверяются чужие варианты, принадлежность вопроса попытке и отсутствие повторяющихся ID. Параллельные ответы и завершение сериализуются блокировкой строки попытки.

## Избранное и история

Добавить вопрос: `POST /questions/{id}/favorite`. Повторный вызов не создаёт дубль. Удаление идемпотентно, пока вопрос существует.

`POST /favorites/attempts`:

```json
{"question_ids": [10, 24, 31]}
```

Допустимы только свои избранные вопросы. Они могут принадлежать разным личным тестам. В новой попытке `test_id=null`, название — «Избранные вопросы». Дальнейшее прохождение совпадает с обычным тестом.

История — `GET /users/me/attempts`. Удаление источника не удаляет результат, выбранные ответы, ключи или пояснения снимка. Удаление самой попытки через `/attempts/{id}` удаляет эту запись истории и её ответы.

## Запуск и проверки

Инструкции окружения и Docker находятся в [корневом README](../README.md). Настройки — [.env.example](.env.example). Подробнее о JWT — [auth/README](api_v1/auth/README.md).

```bash
uv run python -m pytest -q
uv run alembic check
```

Миграция `ab92110c7d02` переносит существующие текстовые вопросы в снимки старых попыток, сохраняя старые результаты. Для старых попыток состояние до прежних правок теста восстановить невозможно: снимок отражает данные, доступные на момент миграции. Новые попытки получают снимок непосредственно при старте.

В API предусмотрены `/health`, CORS и логирование запуска/остановки, ошибок БД, отказов входа и импорта. Пароли, JWT и содержимое загружаемых файлов не пишутся в прикладные логи.
